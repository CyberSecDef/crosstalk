# CROSSTALK

A CLI pipeline for researched discussions between fictional personas using different AI vendors. JEV categorizes source material and checks whether evidence supports extracted claims. The project follows the milestone order in [handoff.md](handoff.md); new manual episodes stop for full-panel transcript review; explicit automatic drafting can inherit the quality gate from an approved prototype.

## Local setup

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'
.venv/bin/crosstalk doctor
```

Copy `.env.example` to `.env` if starting a fresh checkout. The existing project `.env` is used automatically and is gitignored. `doctor` prints only credential presence. `GEMINI_API_KEY` and `GROK_API_KEY` are accepted aliases for Google and xAI. DeepSeek and JEV have their own adapters; local OpenAI-compatible endpoints are supported.

The tested environment is Linux with Python 3.14. Python 3.11+ is declared; the current process-safe budget lock uses Linux/Unix `fcntl`. `requirements-lock.txt` records the installed dependency versions.

## Research

```bash
.venv/bin/crosstalk research \
  --topic 'Should cities charge drivers to enter congested downtown areas?' \
  --sources-file config/research/congestion_pricing_urls.txt \
  --live
```

Use one HTTP(S) URL per line. Curated URLs are the selected research mode for now. A generated query plan records six to twelve research angles even when URLs are curated. The Tavily adapter is available, but its separate credit pricing is not yet enabled under the initial dollar budget.

Research saves evidence passages, extracted claims, JEV decisions, category labels, review flags, embeddings, dossier synthesis, and acceptance results. Claims must pass evidence-support checks to enter the dossier. Deduplication uses embedding similarity above 0.9, a proposition-equivalence check, and a check that newly merged sources support the retained wording. Single-source claims retain their uncertainty.

```bash
.venv/bin/crosstalk research --run-dir runs/<saved-run> --live
.venv/bin/crosstalk inspect runs/<saved-run>
```

Resume uses source checkpoints and request caches. Changing the topic, research settings, or source list requires a new run. Sources that fail to fetch are logged and skipped; existing evidence is reused.

## Discussion

```bash
# M2: Nia and Sam; no interruptions.
.venv/bin/crosstalk discuss runs/<saved-run> --mode two --minutes 5 --live

# M3: host plus all four panelists. Requires M2's automated checks first.
.venv/bin/crosstalk discuss runs/<saved-run> --mode full --minutes 10 --live
```

Discussion subdirectories contain raw turns, transcript JSON/Markdown, bids, drift scores, usage, and a checkpoint. Resume with the same command. Persona YAML files select vendors/models; `config/show.yaml` selects episode settings and respectful, spirited disagreement. Bids default to a pooled DeepSeek call to limit costs; `bidding_mode: independent` collects persona bids concurrently instead. Speech remains generated by each persona's configured vendor.

The director handles recency penalties, speaking-share penalties, host steering, word-boundary interruption cuts, overlapping backchannels, rolling summaries, and private drift reinforcement. A separate listener pass evaluates brief reactions when floor bids do not supply enough: only model-approved reactions are layered onto saved main speech. The original main conversation, reaction bids, and index mapping remain available for inspection. Spoken citation IDs are rejected; references remain metadata. Duration estimates use 150 words/minute; audio timing comes later.

Automated acceptance does not establish that a conversation sounds natural or that every spoken assertion is true. Human review gates M3. Transcript-level fact checking and stance-preserving polish are M4; neither is represented as finished by a draft transcript.

## Spending and validation

Paid commands require `--live`. All initial live tests share `runs/initial_test_budget.jsonl` with the authorized $25 ceiling. Requests reserve conservative peak-price estimates before transmission, including retries. Reservations are not refunded after failures. Keep this ledger when resuming; deleting it resets the local accounting. Providers' billing dashboards remain the authority on actual charges. Unknown model prices block budgeted requests until verified rates are configured.

Initial JEV confidence thresholds and drift rubrics are provisional. Low-confidence judgments remain flagged. The small labeled evaluation uses synthetic examples and does not establish production calibration.

```bash
.venv/bin/pytest -q
.venv/bin/ruff check crosstalk tests scripts
.venv/bin/python -m scripts.live_smoke --live
.venv/bin/python -m scripts.evaluate_decisions --live
```

The live smoke script checks only small API contracts, not episode quality, and uses the shared budget. Cached OpenAI speech clips and a draft MP3/WAV mixer are implemented; human listening acceptance remains required.

### Transcript evidence review

After conversational approval, run `.venv/bin/crosstalk factcheck runs/<saved-run> --live`. This resumes from saved assertion-level checks without regenerating the discussion. Results are in `factcheck_reviewed/factcheck.json` for editorial revisions, or `factcheck_v2/factcheck.json` otherwise, with flagged turns in `transcript_review.md`. Evidence checks use saved passages from referenced and alternative sources; they establish support, not independent truth. Uncertain checks and settled single-source statements require review. Disputes within the next three turns are recorded without erasing the original verdict.

`speech_ready.json` separates plain spoken text from citation metadata. Inline citation annotations are excluded, and bare internal IDs are rejected before synthesis. Natural publication attribution remains part of spoken text. This artifact is not publication approval; audio generation must respect the fact-check report.

### Draft audio preview

Run `.venv/bin/crosstalk audio runs/<saved-run> --live` after M3 approval and transcript evidence checking. Clips are cached by actual text, voice, speed, model, and format. Five prototype built-in voices are configured in `config/voices.yaml`. Plain speech text is validated immediately before each vendor call; citation IDs and claim-reference metadata are never sent to speech synthesis. Outputs include `audio/episode_preview.mp3`, WAV, and `timed_transcript.json`. Repeating a render reuses clips without paying again.

The default preview can retain unresolved evidence flags for private listening review. `--no-preview` refuses to render when the evidence publication gate is closed. No command publishes audio externally. A single light polish pass runs automatically before voicing and is also available via `crosstalk polish`. It uses persona profiles, nearby turns, and voice samples to reduce excessive tics and awkward phrasing while preserving all content and individuality. Originals, rejected edits, and a diff are preserved separately. Its preservation rubric is provisional and edited factual assertions still need evidence review; it does not replace the approved transcript automatically.

Audio uses OpenAI `tts-1` at [$15 per million input characters](https://developers.openai.com/api/docs/models/tts-1), verified 2026-10-05. It does not support emotion instructions. This fallback and other legacy speech models are [scheduled for removal on January 6, 2027](https://developers.openai.com/api/docs/deprecations); the adapter boundary allows a replacement without changing the timeline. ElevenLabs is not configured in this project. The mix uses normal gaps, overlapping interruptions, lowered backchannels, and FFmpeg normalization targeting -16 LUFS/-1.5 dBTP. Word-level forced alignment is not implemented; natural cuts and overlap intelligibility require human listening review.

Polish content and individual-voice judgments must both return preserved with confidence at least 0.9. Empty or extensive rewrites, changed numbers, altered turn metadata, and stale artifacts are rejected. Short listener reactions and already-truncated lines remain unchanged. Repeating the audio command resumes the saved polish rather than rewriting a second time. The voicing stage validates the polish lineage and reads the accepted polished text. Original-draft evidence checks are retained; any edited transcript keeps the publication gate closed until its factual assertions are reviewed.

### Run or resume the complete draft pipeline

```bash
.venv/bin/crosstalk run runs/<saved-run> --from-stage polish --live
.venv/bin/crosstalk run --topic "Should cities charge drivers to enter congested downtown areas?" --sources-file config/research/congestion_pricing_urls.txt --live
```

Stages are research, discussion, editorial, polish, factcheck, and audio. A manually operated new discussion stops for M3 conversational review. Each stage resumes its saved artifacts; speech clips and complete mixes are cached. `pipeline.json` records completion or the stage that stopped. Changed editorial wording is separately audited in `editorial/revision_plan.json`; the approved original is retained. Current checks live in `factcheck_reviewed` for editorial revisions, or `factcheck_v2` otherwise, and evaluate the exact accepted polished text rather than the earlier draft. Original automated verdicts remain visible, with source-specific editorial notes when supplied. Neither corrections nor machine judgments fabricate human publication approval.

### Curated topic discovery and automatic drafts

```bash
.venv/bin/crosstalk topics --sources-file config/research/congestion_pricing_urls.txt --top 5 --live
.venv/bin/crosstalk run --auto --topic "Should cities charge drivers to enter congested downtown areas?" --sources-file config/research/congestion_pricing_urls.txt --prototype-run runs/<approved-prototype> --live
```

Discovery uses the configured curated URLs, with daily saved page snapshots. JEV distinguishes policy choices from factual lookups and evaluates whether defensible opposing positions exist. Ranking combines source recency, publisher presence, and debatability. This is curated-source selection, **not a measure of social popularity**; social/news-feed integrations are not implemented. A small synthetic smoke evaluation must pass before ranking runs. Automatic topic selection additionally requires confirmed human calibration labels in `config/discovery_labels.json`; while those labels are pending, supply an explicit `--topic` for automatic drafting.

`--auto` inherits the development quality gate only from a human-approved M3 prototype with matching personas, models, director settings, and a validated saved fingerprint. Each new episode still must pass mechanical acceptance and evidence checks. It records `automation_quality.json` with `human_review_passed: false`: the original prototype review is not represented as a human review of a new episode. Automatic drafting does not publish externally or override unresolved evidence flags. All commands share the authorized $25 reservation ledger; insufficient remaining budget stops safely at saved checkpoints.

### Interruption bidding evaluation

Pooled and independent bids share an urgency scale. Ordinary rebuttals stay at or below 0.75; specific immediate corrections, clarifications, or questions challenging consequential policy premises may exceed 0.75. Only substantive respond/rebut requests from a different speaker can interrupt. Existing speaking-share balance, cooldown, and persona probability remain in force; acceptance still requires two interruptions for a full prototype. `python -m scripts.evaluate_bidding --live` checks four synthetic cases under the shared budget. Add `--replay-run runs/<saved-run>` to compare three reconstructed episode contexts with their original bids. The evaluation saves outputs without changing the transcript and does not establish production calibration.

Director v3 protects a 17% speaking-share margin once at least 500 words have accumulated: a quieter panelist with a substantive floor request gets priority before more dominant requests. Passes and backchannels never become full speeches to meet a quota. Existing interrupted speech remains recorded with its original cut provenance. Changed director versions require a fresh discussion checkpoint; older saved audio and approved prototype artifacts remain available.

### Local factual review and episode export

These commands run offline and make no vendor calls:

```bash
.venv/bin/crosstalk review runs/<saved-run>
.venv/bin/crosstalk review-import runs/<saved-run> /path/to/crosstalk-review-decisions.json
.venv/bin/crosstalk export runs/<saved-run>
```

Open the generated `review/index.html` in a browser. It includes the audio, flagged claims, exact spoken wording, retrieved source passages, source-specific editorial notes, and before/after corrections. Search or filter the claims, then choose source-supported, opinion, needs correction, or defer. Every decision requires a rationale; source-supported decisions require selected passages, and correction decisions require proposed spoken wording. Browser drafts are stored locally by exact version. Download decisions and import that file to save them in the project. Proposed corrections remain proposals until separately applied and checked.

Decisions bind to the spoken transcript, machine report, and full evidence snapshot. Changed inputs invalidate old decisions. Imports append `review/decision_events.jsonl` and maintain the current decision snapshot without changing machine verdicts or transcript text. An unreviewed claim, defer, or requested correction keeps review incomplete. This explicit review is separate from earlier source assessments and listening approval.

Export creates a versioned ZIP under `exports/`, with MP3/WAV, timed and readable transcripts, source metadata, a deterministic episode summary, factual review, correction audit, polish diff, applicable listening approval, and a SHA-256 manifest. It excludes credentials, caches, request logs, and full raw source pages. Draft export is allowed and clearly records pending review. Use `--require-reviewed` to require current explicit factual decisions and listening approval before packaging. Neither review nor export grants publication approval or publishes externally. Existing ZIPs are preserved; use `--output` for a different destination.


### Automated factual editorial pass

`crosstalk editorial <run> --live` runs after discussion quality acceptance and before speech polish. New full pipelines include it automatically; direct polish/audio also require it. The configurable `editorial.vendor`/`editorial.model` (default Google `gemini-2.5-flash`) retrieves saved source passages and proposes minimal corrections to attribution, causal certainty, study scope, dates and invented firsthand experiences. JEV independently checks factual adequacy/stance (confidence ≥0.8) and individual voice preservation for changed lines (≥0.9). Identical text preserves voice by equality. Known fabricated firsthand and unqualified study-proof phrases are also blocked deterministically. This is separate from the single spoken-flow polish and final exact-spoken evidence check.

Every turn retains its speaker, citation metadata, interruption links, cut provenance and overlap. Accepted edits are audited in `editorial/revision_plan.json`; proposals and validation results are saved in `editorial/editorial_review.json`. Uncertain/rejected edits retain the original wording and stop before polish/speech, with the affected turns listed for review. Mechanical acceptance is checked again after correction. Resuming identical inputs reuses checkpoints; changed evidence, models, personas or text require a new run. Existing manual audited revisions are retained. Running this stage under existing polish/audio without a prior editorial revision requires an isolated new run, preserving approved versions. It does not approve publication, fabricate human review, or automatically resolve final assertion-review decisions.


Editorial revision v6 separates JEV empirical-support checking from relative voice/position checking, with the original 0.8/0.9 thresholds. Ambiguous empirical support fails the evidence rubric; uncertain voice preservation fails the voice rubric. A narrow structural proof permits removing firsthand framing only when every remaining word is identical. One bounded repair attempt includes the exact prior failure; all attempts are saved, and interruption recovery does not restart completed attempts. Sixteen agent-reviewed development examples live in `config/editorial/regression_cases.json`; they are neither human calibration labels nor hardcoded acceptance rules.

The public repository excludes `.env`, generated `runs/`, local project status, and agent/account metadata. Copy `.env.example` locally and supply your own approved prototype when using `--auto`. Automated tests use mocks and require no vendor credentials or spending. FFmpeg is required for audio rendering.


### Editorial regression checks

`python -m scripts.evaluate_editorial --source-run <run> --candidate-run <saved-editorial-run> --live` replays saved author proposals across the full transcript through the current guards and live JEV validation. Optional additional `--candidate-run` inputs supply saved repair proposals. The evaluation marks generation as replayed; it does not claim fresh generation or human approval. Without `--live`, no calls occur.

`python -m scripts.verify_editorial_polish <evaluation-run> --live` verifies accepted editorial edits through one isolated polish pass. It writes only to `polish_validation/`, never renders audio, and cannot unlock production when editorial review remains pending. Identical wording passes by equality; changed wording requires the usual independent content and voice preservation checks. Fresh full-generation tests and replay results remain distinct. Current live tests still require source/voice adjudication: this is conservative assisted editing, not yet a validated unattended episode producer.
